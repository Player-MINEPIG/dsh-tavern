# v2.3.0 — 提示词装配追踪与溯源

这次更新以 **Trace** 为主题，让你看清每次请求使用了什么配置、世界书为何触发，以及提示词的各个段落来自哪里；也让第三方开发者能够使用这些信息制作自己的工具。

## Tavern Trace：看清每次请求的提示词

先展示当次配置，再按需展开世界书触发情况与 Loader 装配结果。可以逐段查看提示词的内容、顺序、字数和来源，帮助排查角色设定或预设未按预期生效的问题。

历史详情读取对应的 DSH 会话记录，不反复保存大角色卡的正文副本；原始记录缺失时会明确提示不可用。

## v3 API：向第三方开放提示词追踪与溯源

新增只读 **v3 元 API**，开放 Tavern Trace 使用的装配记录。第三方可以据此制作逐段提示词查看器，了解某次请求的段落由哪些预设、角色卡字段或世界书条目贡献，而不只是看到当轮绑定了哪些资源。

v1 继续负责当前资源与配置，v2 继续负责 RP 周目操作。v3 专注记录查询与来源识别，本版不提供修改 Loader 装配策略的接口；第三方也可以直接使用 DSH 官方接口观察、调整和贡献段落。[开发接入说明](https://github.com/Player-MINEPIG/dsh-tavern/blob/codex/trace-api-v3/docs/PROMPT_API_V3.md)

## 工作区诊断：集中查看和处理异常

新增 **DT → 诊断**，可以查看异常周目的原因与恢复建议、重新检查或复制报告。侧栏报错摘要可以关闭，异常周目仍保留警告入口，方便稍后处理。

## RP 体验与兼容修复

- 修复旧会话日志缺失时无法新建周目、RP 视图不可用，以及部分异常周目漏标警告的问题。
- 改善 RP 与 HTML 导出的静态面板显示，支持代码围栏中的完整 HTML 文档，并隔离不同面板的样式。
- 兼容标签为空的角色卡，修复空昵称未回退角色名，以及没有下一条有效开场白时仍可点击切换的问题。
- 提示词按 DSH 官方段落格式参与装配，保留预设编排；插件自动生成的来源标识不再发送给模型。

**暂不支持 MVU 变量系统和依赖 JavaScript 的动态 HTML。** 静态 HTML/CSS 可以展示，脚本驱动的数值更新和按钮交互不会执行。

## 升级说明

目标运行环境为 **DSH 0.1.5-rc.1**。升级前停止 Host，并备份 Tavern 数据、RP 工作区及对应的 DSH 会话日志；安装后重启。工作区中的周目引用不能替代会话日志备份。[安装与迁移](https://github.com/Player-MINEPIG/dsh-tavern/blob/codex/trace-api-v3/docs/INSTALLATION.md)

自动回归、真实 Host 与 Chrome 检查已完成，呈现审核已通过。实际第三方插件联调和原生 Windows 验证尚未完成；详细覆盖范围见[验收记录](https://github.com/Player-MINEPIG/dsh-tavern/blob/codex/trace-api-v3/docs/TRACE_REVIEW.md)。
