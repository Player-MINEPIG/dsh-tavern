# 资源位置与装配结果接入

[English](RESOURCE_LAYOUT_en.md)

资源位置由独立 `dsh-prompt-assembler` 实现。Tavern 的 `packages/request-assembler/resource-layout.js` 转发 `normalizeLayout`、`describeResourceLayout`、`withBlockMove`、`positionRows` 和 `configurePosition`，不复制装配逻辑。

编辑器分为「资源位置」与「装配结果」两页。前者直接读取来源声明，列出预设正文类别、角色/用户宏、世界书各位置及已注册的 MVU/模板注入；空位置也能开关和排序。来源解析、身份与投递设置在同页展开。后者加载当前资源，按用户选择的优先级展示正文、来源、最终顺序与排序依据。最近实际请求保持独立只读入口。

策略的 `layout.positions` 保存来源 ID、位置 ID、开关和跟随来源/用户排列选择，不保存资源 ID、激活条目或 MVU revision。来源 descriptor 可声明 `positions`，既有来源目录接口直接返回。MVU 当前提供变量状态与更新指令的独立注入；嵌入世界书/模板正文的变量值仍随宿主内容定位。

`layout.priority` 保存用户可拖拽排序的四项规则：用户位置、预设插槽、资源自带位置、来源默认顺序。运行时原生历史、工具事务与留存约束单独说明且始终有效。新策略提供可修改的初始列表，旧策略保留原选择。预览与实际请求共用解析和排序；标准后端的当前结果仍受原生投递与 context 快照复用限制，不冒充已发送请求。旧具体资源覆盖保留兼容入口，可明确清除。

标准后端选择「保留来源身份」时，system 内容归入历史前的 system 区域，user 内容归入原生 user 投递区域；插槽优先级在角色与运行时边界内决定顺序，不要求为跨边界插槽改写身份。世界书深度也不能覆盖此身份选择。选择「允许按位置适配」时，才按插槽前后及深度 0/1 映射身份。官方基础指令的开关独立于身份处理，始终可以关闭。

装配结果中的错误会保留到重新校验成功；修改或保存配置不代表校验通过。界面在应用当前策略或恢复默认策略前，使用当前会话/开场草稿重新预览，失败则不应用。校验不包含未发送输入，未来资源变化仍由实际请求重新校验。

集成方需将 assembler 依赖更新到包含这些 API 的版本，并统一生成 package/lockfile 与客户端 bundle。历史筛选由独立历史策略模块负责。验证：`node --test test/resource-layout-*.test.mjs`；完整接口、类型与 stock/core Host 验证见 assembler 的 `docs/RESOURCE_LAYOUT.md` 和英文对应文档。

排序按保存的列表逐轮执行；前一轮已定位的资源不再由后续策略移动。结果中的 `sortingStages` 记录每轮定位的节点。资源卡片在加载具体资源前展示来源声明的稳定性；结果卡片直接说明已有原生消息、系统更新、上下文/步骤前注入、仅本次请求和单独留存的装配快照是否进入原生历史。两个列表均只通过拖拽调整顺序，不提供上移下移按钮。
