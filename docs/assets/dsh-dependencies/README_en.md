# DSH native dependencies and upgrade impact

[中文](README.md) · [Interactive architecture](architecture.en.html) · [Editable JSON](architecture.en.json) · [Overall architecture](../../ARCHITECTURE_en.md)

This diagram describes the Tavern **2.4.2** checkout contract for DSH **0.1.7-rc.1**, Cordis **4.0.4**, and `dsh-util-crypto` **0.1.7-rc.1**. It is a map of Tavern's consumers and their semantic dependencies, not a publication or blanket runtime-acceptance claim. Diagram SRC entries are verified local source labels with hyperlinks disabled; the matrix uses repository-relative Tavern links. Official DSH authority is the immutable [target tag](https://github.com/deepseek-ai/deepseek-harness/tree/dsh-v0.1.7-rc.1), especially [Agent loop](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.7-rc.1/packages/core/agent-loop/src/agent.ts) and [V3→V4 migration](https://github.com/deepseek-ai/deepseek-harness/blob/dsh-v0.1.7-rc.1/packages/session/session-format-v3-to-v4/README.md). No unpublished Tavern commit is presented as a working GitHub link.

Download the HTML and open it in a browser for source labels, node search, themes and exports. GitHub's file view does not execute interactive HTML. This directory holds both languages and editable sources; the existing `docs/assets` packaging rule includes them.

## Reading the diagram

The main path is **Tavern browser → Tavern HTTP/loader → DSH execution and controllers**. Arrows express their labeled calls, reuse or reads, rather than every event direction or every module import. Playthroughs and Trace read DSH through the loader/Host port; “read via API” is not browser filesystem access. The tools/sandbox node represents DSH capabilities; Tavern's loader owns the RP guard policy.

High/medium/low are maintenance assessments, not failure probabilities or percentages of code. Colors identify component categories, not risk. Public interfaces can still carry strong ordering and data coupling.

| Level | Basis | Upgrade implication |
| --- | --- | --- |
| High | Direct service calls, event/store structures, execution order, history coordinates or safety semantics | Compare upstream changes first; typically needs adapter work and real Host/browser checks |
| Medium | Isolated through a Tavern port or plain objects, but interprets DSH messages and coordinates | Projections, validation or migration may change even when signatures remain stable |
| Low | Owned resources, configuration and persistence; composition roots handle DSH integration | Usually retain domain models and check adapter inputs/outputs |
| No direct dependency | Pure parsing, normalization, macros and matching without DSH runtime reads | Independently testable; end-to-end behavior still depends on loader input and assembly |

## Parts that can remain stable

- Pure parsing/matching in `tavern-format` and `world-book` has no direct DSH runtime dependency. Adapt changed DSH inputs at the loader boundary first; do not move Session access or hooks into pure libraries.
- Resource models/storage/APIs in `preset`, `character`, `user`, `world-book-library` and `session-template` have low direct coupling. Browser mounting and final-request integration still depend on composition roots.
- `play` does not import DSH and uses injected Host ports, but timeline/session-format validation retains semantic coupling. Trace recorders receive plain data while interpreting official event shapes; the body reader depends on injected `sessionController.inspect()`.
- Tavern storage holds resources, selections, settings and Trace metadata/references. The RP workspace holds catalog/timeline, presentation metadata and explicitly imported records. DSH owns actual chat/system history. Migration and backup must account for all three stores and inherited history, rather than only the Tavern directory.
- Tavern does not replace the native composer, tool execution, model provider, Remote transport or DSH storage engine. It depends on them indirectly through public services/stores, so semantic changes can still matter. `/v2/chrome/events` is Tavern-owned SSE, not a DSH Remote event.

[Architecture tests](../../../test/architecture.test.mjs) provide partial static protection for these boundaries; they cannot establish runtime compatibility.

## Breaking-update review order

1. **Pin both versions.** Retain this Tavern commit and pin candidate DSH to a tag/commit. Compare Cordis, client root exports, injected services, slot owners, store fields and Host controllers. Do not stop at import lists.
2. **Check data semantics first.** If formats, inherited prefixes, seq or system/message projections change, assess history references and migration before fork/swipe/Trace acceptance. Do not reuse old seq as new seq or infer byte offsets.
3. **Check assembly and execution ordering.** Cover first claims, cancel/replace/steer, multiple steps, retries, terminal events, forks and delegated subagents. Compare final LLM requests with official history; successful Trace metadata capture does not prove body-reference correctness.
4. **Check safety and failure paths.** Review new/renamed tools, guards/cancellation, RP entry/exit and sandbox restoration. Distinguish absent capabilities, disabled enhancements and partially completed writes. A failed fork cleanup can leave a child, and multi-file playthrough operations are not one transaction.
5. **Check real UI and uninstall fallback.** In the target Web Host/browser, exercise native/play modes, default RP, manual native/Trace selection, empty openings, partial streaming, errors, session/workspace switching, locale changes and disposal. Check desktop directory picking in that environment separately. Native sessions must remain readable after uninstall.

## Maintaining the sources

The two JSON specifications share stable node/edge IDs and topology with localized wording. `meta.repository.link_mode: "local-only"` keeps source labels without broken unpublished GitHub links; `revision` identifies the locally inspected source snapshot for deterministic verification. When refreshing the snapshot, update both revisions, verify every source path at that commit, and synchronize the matrix's relative links. Only switch to immutable web links after that revision is actually published.

Run from the repository root, with `ARCHIFY_ROOT` pointing to the installed skill directory. Validate and deliver both languages:

```sh
node "$ARCHIFY_ROOT/bin/archify.mjs" validate architecture docs/assets/dsh-dependencies/architecture.en.json --quality showcase --repo-root . --json
node "$ARCHIFY_ROOT/bin/archify.mjs" deliver architecture docs/assets/dsh-dependencies/architecture.en.json docs/assets/dsh-dependencies/architecture.en.html --quality showcase --repo-root . --json
node "$ARCHIFY_ROOT/bin/archify.mjs" visual-check docs/assets/dsh-dependencies/architecture.en.html --json
```

For Chinese, replace `en` with `zh-CN` in filenames. Deterministic delivery checks, browser evidence and perceptual review are separate checks. Move screenshots, execution receipts and acceptance records into Git-ignored `.local/`; do not commit them as maintained documentation or installation content. Retain source specifications and standalone HTML; readers need neither archify nor external scripts.
